# Alert

A persistent, inline status message for surfacing information, confirmations, warnings, or errors
that live alongside your content — inside a page, a form, or a card. Alert always stays in
document flow; it never overlays other content and never auto-dismisses on its own. There isn't a
toast/notification component in this library yet for transient, auto-dismissing messages — Alert
is for content that should remain visible until the user (or your application logic) removes it.

## Import

```tsx
import { Alert } from '#src/components/alert';
```

## Composition

`Alert` is a compound component. `Alert` itself is `Alert.Root`, and the other slots hang off of
it:

```
Alert (Alert.Root)
├── Alert.Icon (optional)
├── Alert.Content
│   ├── Alert.Title
│   ├── Alert.Description (optional)
│   └── Alert.Actions (optional)
└── Alert.CloseButton (optional)
```

## Usage

```tsx
import { Alert } from '#src/components/alert';

function Example() {
  return (
    <Alert variant="default">
      <Alert.Icon />
      <Alert.Content>
        <Alert.Title>Scheduled maintenance</Alert.Title>
        <Alert.Description>The dashboard will be unavailable for 10 minutes tonight at 11pm.</Alert.Description>
      </Alert.Content>
    </Alert>
  );
}
```

### Variants

Four status variants are available: `default` for neutral, informational messaging, and
`success`, `warning`, and `danger` for the corresponding outcomes. Each variant uses a softly
tinted background so it reads clearly without competing with the rest of the page.

<Canvas of={AlertStories.AllVariants} />

### Icons

`Alert.Icon` automatically shows an icon matching the alert's `variant` — you don't need to pass
anything to get a sensible default. Pass your own icon as its children to override that default.

<Canvas of={AlertStories.WithCustomIcon} />

A title with no description still lays out correctly:

<Canvas of={AlertStories.TitleOnly} />

### Actions

To give the reader something to do about the message — retrying a failed action or undoing a
change — place regular `Button`s inside `Alert.Actions`, as the last child of `Alert.Content`.

<Canvas of={AlertStories.WithActions} />

### Inside a Card

Alert doesn't need any extra configuration to sit correctly inside a `Card` or any other surface —
its color treatment holds up regardless of what it's layered on top of.

<Canvas of={AlertStories.OnCards} />

### Close button

`Alert.CloseButton` renders a dismiss affordance at the trailing edge of the alert. It's purely
presentational — pass it as a plain sibling after `Alert.Content` and it renders standalone even
without an `onPress` handler:

<Canvas of={AlertStories.WithCloseButton} />

### Dismissing an alert

Alert has no built-in dismissed state of its own. To make an alert actually go away, wire
`Alert.CloseButton`'s `onPress` to state in the parent and stop rendering the `Alert` once it's
dismissed:

`Alert.Root` accepts any other standard `<div>` prop.

### `Alert.Icon`

Shows a default icon matching the parent `Alert`'s `variant`. Pass `children` to render your own
icon instead. Accepts standard `<div>` props otherwise.

### `Alert.Content`, `Alert.Title`, `Alert.Description`, `Alert.Actions`

Accept standard `<div>` props, with `children` required on all four.

### `Alert.CloseButton`

Renders as the repo's `Button` with a close icon. Accepts any `Button` prop except `children`,
`variant`, and `isIcon`, which are fixed. `onPress` is optional — pass it to actually dismiss the
alert (see [Dismissing an alert](#dismissing-an-alert)); without it, the button renders but does
nothing.
