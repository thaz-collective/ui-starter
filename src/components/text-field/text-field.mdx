# Text Field

A single-line text input built on top of `react-aria-components`' `TextField`, styled with
`tailwind-variants`. It handles labeling, descriptions, validation error messaging, and the
required/disabled/read-only/invalid states that come from React Aria, and exposes them as a small
set of composable slots so you control exactly what gets rendered.

## Import

```tsx
import { TextField } from '#src/components/text-field';
```

## Composition

`TextField` is a compound component. `TextField` itself is `TextField.Root`, and the other slots
hang off of it:

```
TextField
├── TextField.FieldContainer
│   ├── TextField.Label
│   └── TextField.Input
├── TextField.Description (optional)
└── TextField.FieldError (optional)
```

`TextField.RootDebounced` is a drop-in alternative to `TextField.Root` for cases where you want to
debounce `onChange` (for example, wiring the field up to a network request) — see
[Debounced input](#debounced-input) below.

Every slot must be rendered inside `TextField` / `TextField.Root` — they read shared context from
React Aria and will not work standalone.

## Usage

```tsx
import { useState } from 'react';

import { TextField } from '#src/components/text-field';

function Example() {
  const [value, setValue] = useState('');

  return (
    <TextField
      className="w-64"
      value={value}
      onChange={setValue}
    >
      <TextField.FieldContainer>
        <TextField.Label>{'Full name'}</TextField.Label>
        <TextField.Input placeholder="Jane Smith" />
      </TextField.FieldContainer>
      <TextField.Description>{'Used on your public profile.'}</TextField.Description>
    </TextField>
  );
}
```

`TextField` is a controlled component — `value` and `onChange` are required. There is no
`defaultValue`/uncontrolled mode; own the state yourself, as shown above.

### Label placement

`TextField.Label` and `TextField.FieldContainer` are required and must be nested together —
`TextField.Label` alongside `TextField.Input`, inside `TextField.FieldContainer`. The container
tracks focus and value state on its children via CSS (`:focus`, `:not(:placeholder-shown)`) to
float the label above the input, so the label, input, and container need to stay together — don't
split them apart or render the label outside the container.

## States

`isRequired`, `isDisabled`, `isReadOnly`, and `isInvalid` are passed to `TextField` /
`TextField.Root` (not `TextField.Input`) — they flow down through React Aria context to every
slot, which is how `TextField.FieldError` knows to show itself, `TextField.Description` knows to
hide itself, and the label/border styling responds automatically.

### Required

Adds a `*` after the label and sets `aria-required` on the input.

## Debounced input

Use `TextField.RootDebounced` in place of `TextField.Root` when `onChange` triggers something
expensive (a search request, autosave, etc.) and you want to debounce it without debouncing the
visible keystrokes in the input itself:

```tsx
import { TextField } from '#src/components/text-field';

function Example() {
  const [value, setValue] = useState('');

  return (
    <TextField.RootDebounced
      value={value}
      onChange={setValue}
      debounceOptions={{ wait: 300 }}
    >
      <TextField.FieldContainer>
        <TextField.Label>{'Search'}</TextField.Label>
        <TextField.Input />
      </TextField.FieldContainer>
    </TextField.RootDebounced>
  );
}
```

The input itself updates immediately on every keystroke; `onChange` (and therefore `value`) only
fires after `wait` milliseconds of inactivity. `debounceOptions` accepts the same options as
`@tanstack/react-pacer`'s `useDebouncedCallback` (`wait` defaults to `300`).

`TextField.Root` accepts any other prop supported by React Aria Components'
[`TextField`](https://react-spectrum.adobe.com/react-aria/TextField.html).

### `TextField.Input`

Renders an `<input>`. Accepts standard `<input>` props (`type`, `placeholder`, `autoComplete`,
etc.) via React Aria Components' `Input`.

### `TextField.Label`, `TextField.Description`, `TextField.FieldError`

Render text content (`children`); styling responds automatically to the parent field's state, no
extra props required beyond standard `className`/`children`.
