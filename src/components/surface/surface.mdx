# Surface

A plain `<div>` that sets `--surface`/`--field` CSS custom properties (and their `-border`,
`-foreground`, `-hover` counterparts) to one step of a five-layer elevation scale, so nested
content — including other components that read `bg-surface`/`bg-field` — automatically picks up
the right layered color without prop-drilling.

## Import

```tsx
import { Surface } from '#src/components/surface';
```

## Usage

```tsx
import { Surface } from '#src/components/surface';

function Example() {
  return (
    <Surface
      variant="default"
      className="rounded-lg border border-surface-border p-4"
    >
      {'Content'}
    </Surface>
  );
}
```

## Variants

Each variant maps `--surface` to one step of the `--surface-default` → `--surface-quinary` scale
defined in the theme, and `--field` one step further — so a `Surface` in `secondary` gives fields
inside it (inputs, containers reading `bg-field`) the `tertiary` tone, keeping fields visually
distinct from the surface they sit on.

`transparent` renders no background at all — useful when you only want the elevation variables
without painting a background (e.g. an overlay that should show what's behind it).

## Nesting

Because each `Surface` only sets CSS variables (it doesn't hardcode colors), stacking `Surface`s
inside each other creates a visible elevation ladder for free — each level just reads the
variables its nearest `Surface` ancestor set.
