# Number Field

A numeric input built on top of `react-aria-components`' `NumberField`, styled with
`tailwind-variants`. It handles labeling, descriptions, validation error messaging, locale-aware
number formatting/parsing, and increment/decrement stepper buttons, and exposes them as a small
set of composable slots so you control exactly what gets rendered.

## Import

```tsx
import { NumberField } from '#src/components/number-field';
```

## Composition

`NumberField` is a compound component. `NumberField` itself is `NumberField.Root`, and the other
slots hang off of it:

```
NumberField
├── NumberField.FieldContainer
│   ├── NumberField.Label
│   ├── NumberField.Input
│   └── NumberField.StepButtons
│       ├── NumberField.IncrementButton
│       └── NumberField.DecrementButton
├── NumberField.Description (optional)
└── NumberField.FieldError (optional)
```

`NumberField.RootDebounced` is a drop-in alternative to `NumberField.Root` for cases where you
want to debounce `onChange` (for example, wiring the field up to a network request) — see
[Debounced input](#debounced-input) below.

`NumberField.FieldContainer`, `NumberField.Label`, `NumberField.Description`, and
`NumberField.FieldError` are the same shared components used by
[`TextField`](/?path=/docs/component-textfield--docs) — they only care about being nested inside
a field root and its container, both of which `NumberField.Root` and `NumberField.FieldContainer`
provide, so they work here unmodified.

Every slot must be rendered inside `NumberField` / `NumberField.Root` — they read shared context
from React Aria and will not work standalone.

## Usage

```tsx
import { useState } from 'react';

import { NumberField } from '#src/components/number-field';

function Example() {
  const [value, setValue] = useState(0);

  return (
    <NumberField
      className="w-64"
      value={value}
      onChange={setValue}
    >
      <NumberField.FieldContainer>
        <NumberField.Label>{'Quantity'}</NumberField.Label>
        <NumberField.Input placeholder="0" />
        <NumberField.StepButtons>
          <NumberField.IncrementButton />
          <NumberField.DecrementButton />
        </NumberField.StepButtons>
      </NumberField.FieldContainer>
    </NumberField>
  );
}
```

`value`/`onChange` are optional on `NumberField` / `NumberField.Root` — omit them for an
uncontrolled field.

`value`/`onChange` are required for `NumberField.RootDebounced` — see
[Debounced input](#debounced-input) below.

### Label placement

`NumberField.Label` and `NumberField.FieldContainer` are required and must be nested together —
`NumberField.Label` alongside `NumberField.Input`, inside `NumberField.FieldContainer`. The
container watches its children for focus and content and floats the label above the input in
response, so the label and container need to stay together — don't split them apart or render the
label outside the container.

Detecting "has content" this way relies on the input actually having a `placeholder`, which is
why `placeholder` is a required prop on `NumberField.Input` — pass `placeholder=" "` if you don't
want visible placeholder text.

### Stepper buttons

`NumberField.StepButtons` is an optional wrapper that stacks `NumberField.IncrementButton` and
`NumberField.DecrementButton` along the trailing edge of `NumberField.FieldContainer`. They call
React Aria's built-in `increment`/`decrement` handlers via the `slot` prop, so no `onPress` wiring
is required — just render them inside `NumberField.FieldContainer`, after `NumberField.Input`.
Omit `NumberField.StepButtons` entirely for a plain numeric input with no visible steppers (the
field remains steppable with the arrow keys and mouse wheel).

### Formatting

Pass `formatOptions` (the same shape as `Intl.NumberFormat`'s options) to format the displayed
value — e.g. as currency. The formatted text is parsed back into a number automatically as the
user types.

## States

`isRequired`, `isDisabled`, `isReadOnly`, and `isInvalid` are passed to `NumberField` /
`NumberField.Root` (not `NumberField.Input`) — they flow down through React Aria context to
every slot, which is how `NumberField.FieldError` knows to show itself,
`NumberField.Description` knows to hide itself, and the label/border/stepper-button styling
responds automatically.

### Required

Adds a `*` after the label and sets `aria-required` on the input.

## Debounced input

Use `NumberField.RootDebounced` in place of `NumberField.Root` when `onChange` triggers
something expensive (a search request, autosave, etc.) and you want to debounce it without
debouncing the visible keystrokes in the input itself:

```tsx
import { NumberField } from '#src/components/number-field';

function Example() {
  const [value, setValue] = useState(0);

  return (
    <NumberField.RootDebounced
      value={value}
      onChange={setValue}
      debounceOptions={{ wait: 300 }}
    >
      <NumberField.FieldContainer>
        <NumberField.Label>{'Quantity'}</NumberField.Label>
        <NumberField.Input placeholder="0" />
      </NumberField.FieldContainer>
    </NumberField.RootDebounced>
  );
}
```

The input itself updates immediately on every keystroke; `onChange` (and therefore `value`)
only fires after `wait` milliseconds of inactivity. `debounceOptions` accepts the same options
as `@tanstack/react-pacer`'s `useDebouncedCallback` (`wait` defaults to `300`).

`NumberField.Root` accepts any other prop supported by React Aria Components'
[`NumberField`](https://react-spectrum.adobe.com/react-aria/NumberField.html).

### `NumberField.Input`

Renders an `<input>`. `placeholder` is required — the label needs it to detect whether the field
is empty (see [Label placement](#label-placement)). Accepts standard `<input>` props via React
Aria Components' `Input`.

### `NumberField.StepButtons`, `NumberField.IncrementButton`, `NumberField.DecrementButton`

`StepButtons` is a plain wrapper `<div>`. `IncrementButton`/`DecrementButton` render a
`react-aria-components` `Button` wired to the field's `increment`/`decrement` slot — no
`onPress` needed. Both accept standard `Button` props (e.g. `aria-label` overrides) except
`slot` and `children`, which are set internally.

### `NumberField.Label`, `NumberField.Description`, `NumberField.FieldError`

Render text content (`children`); styling responds automatically to the parent field's state, no
extra props required beyond standard `className`/`children`.
