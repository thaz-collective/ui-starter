# TanStack Form Integration

`useAppForm` (exported from `#src/configs/tanstack-form`) is a pre-configured
`@tanstack/react-form` v2 form hook. It registers a field adapter for every form-capable component
in this library, so a field can be rendered with `form.AppField` + the matching adapter component
instead of hand-wiring `value`/`onChange`/`isInvalid` yourself.

<H2 id="import">Import</H2>

<pre>
  <code>{`import { useAppForm } from '#src/configs/tanstack-form';`}</code>
</pre>

<H2 id="registered-adapters">Registered adapters</H2>

Each adapter lives at `src/common/lib/form/<name>.tsx`. It takes a `field` prop (the
`@tanstack/react-form` field API for that value type, via `FieldWithValue<T>`) plus most of the
underlying component's own root props, and wires `field.value`/`field.handleChange`/
`field.handleBlur`/`field.meta.isInvalid` onto the component's native controlled props
(`value`/`onChange`, or `isSelected`/`onChange` for the boolean toggles, or
`selectedKey`/`onSelectionChange` for Select/ComboBox). Adapters for compound components
(everything except `Checkbox`, `Switch`, and `Slider`) also accept `label` and `description` props
and render the full `Label`/`Group`/`Description`/`FieldError` composition internally, so you don't
repeat that boilerplate at every call site.

<H2 id="example">Example</H2>

<pre>
  <code>{`import { useAppForm } from '#src/configs/tanstack-form';

interface SignUpFormValues {
  name: string;
  bio: string;
  isSubscribed: boolean;
}

function SignUpForm() {
  const form = useAppForm({
    defaultValues: {
      name: '',
      bio: '',
      isSubscribed: false,
    } satisfies SignUpFormValues,
    onSubmit: ({ value }) => {
      console.log('submitted', value);
    },
  });

  return (
    <form
      onSubmit={(event) => {
        event.preventDefault();
        event.stopPropagation();
        form.handleSubmit();
      }}
      className="flex w-80 flex-col gap-5"
    >
      <form.AppField name="name">
        {(field) => (
          <field.TextField
            field={field}
            label="Full name"
            description="Used on your public profile."
          />
        )}
      </form.AppField>

      <form.AppField name="bio">
        {(field) => (
          <field.SearchField
            field={field}
            label="Search bio topics"
          />
        )}
      </form.AppField>

      <form.AppField name="isSubscribed">
        {(field) => <field.Switch field={field}>Subscribe to updates</field.Switch>}
      </form.AppField>

      <button type="submit">Create account</button>
    </form>
  );
}`}</code>
</pre>

The `field` prop passed to each adapter is the callback argument from `form.AppField`, not
`form.state.fieldMeta` or a raw `useField()` call — `useAppForm`'s `AppField` API supplies it
already scoped to the given `name`.

<H2 id="manual-wiring">Manual wiring (without an adapter)</H2>

The adapters are a convenience, not a requirement. Any field can be wired manually with
`form.Field` (the base `@tanstack/react-form` primitive, available even without `useAppForm`) and
the component's own props directly — useful when a field needs composition the adapter doesn't
expose (e.g. a custom `Select.Section` layout, or a `Slider` with multiple thumbs, which
`SliderAdapter` doesn't support):

<pre>
  <code>{`<form.Field name="age">
  {(field) => (
    <NumberField.Root
      value={field.state.value}
      onChange={field.handleChange}
      onBlur={field.handleBlur}
      isInvalid={!field.state.meta.isValid}
    >
      <NumberField.Label>Age</NumberField.Label>
      <NumberField.Group>
        <NumberField.Input />
      </NumberField.Group>
      <NumberField.FieldError>
        {field.state.meta.errors.map((error) => error.message).join(', ')}
      </NumberField.FieldError>
    </NumberField.Root>
  )}
</form.Field>`}</code>
</pre>

For the full design rationale behind the adapter shapes — why each one picks the controlled-value
type it does (e.g. `Select`/`ComboBox` storing the selection `Key` rather than the full option
object, or `DateTimePicker`/`TimeField` using RAC's own `DateValue`/`TimeValue` instead of a plain
JS `Date`) — see `plans/tanstack-react-form-v2-integration.md`.
